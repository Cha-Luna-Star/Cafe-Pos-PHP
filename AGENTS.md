# Cafe POS project instructions

## UI design

- Load [assets/css/ui.css](assets/css/ui.css) on every user-facing page. Reuse its tokens for typography, spacing, surfaces, borders, and focus states.
- Use `.ui-button` with a semantic `data-tone` for buttons and button-like links. Use `.ui-button-sm` for compact row actions. Keep labels and accessible names descriptive and carry the same styles into controls generated by JavaScript.
- Use `positive` (#16a34a) for Apply, Create, Add, Save, Confirm, Restore, and Complete. Use `danger` (#dc2626) for Delete, Remove, Cancel, Void, and resets that discard changes. Use `info` (#2563eb) for Edit, Adjust, Update, and Manage. Use `warning` (#d97706) for Archive, Deactivate, and caution. Use the default gray (#6b7280) for Back, Close, Clear Filters, and Reset Filters. Disabled buttons use light gray (#e5e7eb). Use `outline` for secondary actions such as exports and pagination.
- Use `.ui-page`, `.ui-panel`, `.ui-field`, `.ui-dialog`, and `.ui-badge` for shared layouts and components. Use `.ui-choice` for selectable filters and `.ui-filter-bar` for grouped filters. Use labeled controls, visible keyboard focus, and status text alongside color. Keep transitions short and respect reduced-motion preferences.
- Keep table headers legible and column widths stable during sorting. On narrow screens, wrap controls and scroll dense tables within their own panels. Keep page-specific layout in the page stylesheet.
- Preserve action permissions, form names, event hooks, and print layouts when changing presentation. Check desktop, tablet, mobile, keyboard interaction, and dynamic states when updating shared components.

## Login page

- Use the existing Coffee-Up logo and a warm brand panel beside the white sign-in form. Stack the panels on narrow screens.
- Keep visible field labels and a full-width positive Sign In button. Provide a keyboard-accessible eye icon that stays visible in both password states and inline field errors.
- Keep invalid credentials feedback generic. Disable Sign In while a valid form submission is pending and restore it when the page is revisited. Preserve the existing authentication, session, CSRF, and redirect behavior.

## Dashboard

- Keep the Manila date in the shared header. Link summary cards and alerts to their corresponding filtered pages and show stock-management shortcuts only to authorized roles.
- Use white panels and a responsive grid for summary cards, charts, transactions, and alerts. Keep button and badge colors aligned with the shared UI.
- Use server-aggregated SQL Server data. Report sales and average order value from completed orders, and label all-order counts and the selected period clearly.
- Keep sales charts usable by pointer and keyboard and include a data table. Show explicit empty, loading, and error states. Bound ranked and recent lists and reuse existing report queries where possible.

## New Order (POS)

- Show available, non-archived products with their local images and stock labels. Use a neutral placeholder for items without photos, and keep out-of-stock products visible and disabled.
- Use a responsive menu grid and a sticky cart when screen width permits. Keep size, temperature, quantity, and removal controls inline and use the shared button tones and visible focus styles.
- Show subtotal, applied order discount, included VAT, total, and cash change. Display the prices charged by checkout and keep the server authoritative for pricing, stock, and payment.
- Validate payment details before confirmation, lock checkout during submission, preserve the cart on failure, and reset it after a successful order. Keep the receipt printable.
